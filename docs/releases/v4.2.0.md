**rconsole 4.2** lets you keep your local account when you switch to single sign-on.

## New

- **Link a local account to SSO.** Signing in with authentik (or another provider) as a user with the same name as a local account used to create a second account, `name-2`. Now you can sign in with your password, open **Settings → Account** and click **Link to authentik**: after signing in there, the provider user opens your existing account, with its history, from then on. Its password and 2FA here are removed and its role follows the provider's groups. An account the provider user already got (`name-2`) is merged into it.
- **`node cli.js user link <local> <sso-account>`** does the same on the server, for an account that already got duplicated. `user unlink <name>` reverses it.

## Better

- When a provider sign-in lands on a new `-2` account because a local account has the name, the rconsole log says so and how to link them.

Same names are never linked automatically: a provider user called `admin` must not become your local admin. Linking needs the password of the local account and the provider sign-in, or shell access to the server.
